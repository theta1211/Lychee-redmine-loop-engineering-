# 要件定義書：Redmine連携 自動開発ループ

## 1. 概要
終業時にRedmineのチケット番号を指定しておくだけで、タスクスケジューラが定期的に
GitHub Copilot CLIを起動し、AIが自動で実装作業を進めてくれる仕組みを構築する。

## 2. 背景・目的
- 開発者が離席している時間（夜間など）を活用し、AIに開発作業を代行させたい。
- 人手を介さずに「チケット指定 → 定期実行 → 実装 → 進捗記録」までを自動化する。

## 3. 登場する要素
| 要素 | 役割 |
|---|---|
| 利用者（開発者） | 終業時に対応させたいRedmineチケット番号を指定する |
| Redmine | チケット（要件・仕様・進捗）の管理台帳 |
| タスクスケジューラ（OS標準） | 指定した間隔でAI起動処理を定期実行する |
| GitHub Copilot CLI | 実際にコード実装・修正・コミットを行うAIエージェント |
| 対象Gitリポジトリ | 実装対象のソースコード |

## 4. 全体の流れ
1. 利用者が終業時に「対応させたいRedmineチケット番号」を指定する（設定ファイル等に記載）。
2. タスクスケジューラが一定間隔（例：30分ごと）でループ処理を起動する。
3. ループ処理が指定チケット番号をRedmineから取得し、内容（タイトル・説明・ステータス）を確認する。
4. 未完了のチケットに対して、GitHub Copilot CLIを起動し実装作業を行わせる。
5. 実装結果をコミット（必要に応じてプッシュ）し、作業内容をRedmineにコメントとして記録する。
6. チケットが完了条件を満たしたらステータスを更新し、次回以降はスキップする。

```
[利用者]
   │ チケット番号を指定
   ▼
[設定ファイル] ← 終業時に更新
   │
   ▼ (定期実行)
[タスクスケジューラ] ──起動──▶ [ループ処理スクリプト]
                                   │
                    ┌──────────────┼───────────────┐
                    ▼              ▼               ▼
              [Redmine API]  [GitHub Copilot CLI] [Gitリポジトリ]
              チケット取得      実装・コミット        作業対象
              進捗コメント登録
```

## 5. 機能要件
| ID | 要件 |
|---|---|
| F-01 | 利用者が処理対象のRedmineチケット番号を1件以上指定できること |
| F-02 | タスクスケジューラにより、設定した間隔で自動的にループ処理が起動されること |
| F-03 | ループ処理はRedmine APIからチケット情報（タイトル・説明・ステータス）を取得できること |
| F-04 | 取得したチケット内容をもとに、GitHub Copilot CLIへ実装指示を渡し実行できること |
| F-05 | 実装結果をGitにコミットできること（設定によりプッシュも可能） |
| F-06 | 作業結果（実施内容・成功/失敗）をRedmineのチケットにコメントとして記録できること |
| F-07 | チケットが完了（実装完了・レビュー待ち等）した場合、以降の自動処理対象から除外できること |
| F-08 | 実行ログを残し、後から処理内容を確認できること |

## 6. 非機能要件
| ID | 要件 |
|---|---|
| N-01 | Redmine APIキー等の認証情報は設定ファイル・環境変数等で安全に管理すること（平文コミット禁止） |
| N-02 | 1回のループ処理が異常終了しても、次回のスケジュール実行に影響を与えないこと |
| N-03 | 同時に複数のループ処理が二重起動しないこと（多重実行防止） |
| N-04 | 処理対象チケット数やCopilot CLIの実行時間が増えても、タイムアウト等で安全に処理を打ち切れること |

## 7. 制約事項
- GitHub Copilot CLIおよびRedmineのAPI利用制限（レートリミット等）に従うこと。
- 自動コミット・プッシュを行う場合、対象ブランチや権限は事前に利用者が明示的に設定すること。
- 実装内容のマージ判断（PRの承認等）は人が行う（完全自動マージは対象外）。

## 8. スコープ外
- Redmineチケットの起票・要件整理そのものの自動化（本仕組みは「指定されたチケット」を処理する）。
- 複数人での同時利用・権限管理機能。
- Redmine以外の課題管理ツールとの連携。

## 9. 今後の検討事項
- 処理対象チケットの指定方法（設定ファイル／Redmineのステータスやラベルでの自動検出）の詳細化。
- 実装失敗時のリトライ方針・エスカレーション方法。
- 通知手段（Slack等）の要否。
