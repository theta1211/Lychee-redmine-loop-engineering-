# 要件定義書：Redmine連携 自動開発ループ

## 1. 概要
Web画面でRedmineチケット番号・実行順序・使用するAIモデルを指定しておくと、
Windowsのタスクスケジューラが定期的に起動する実行エンジンが、GitHub Copilot CLIを使って
実装・レビュー・修正を自動で行い、コミット・プッシュまで実施する仕組みを構築する。

## 2. 登場する要素
| 要素 | 役割 |
|---|---|
| Web画面（キュー管理アプリ） | チケット番号・実行順序・AIモデルの指定、実行状況の確認、キューの一時停止/中断操作を行う |
| 実行エンジン（バッチ処理） | タスクスケジューラから起動され、キューの先頭チケットを実際に処理する |
| GitHub Copilot CLI | 実装・レビューを行うAIエージェント本体（利用モデルは切替可能） |
| Redmine（既存システム） | チケット管理・進捗コメントの記録先。新規構築はせず既存サーバーを利用する |
| 対象Gitリポジトリ | 実装対象。当面は1リポジトリに固定 |
| Windowsタスクスケジューラ | 実行エンジンを一定間隔で起動するトリガー |
| 利用者 | Windows統合認証で識別。キュー自体は全利用者共通の1つ |

## 3. 全体構成図
```
[利用者] ──Windows認証でログイン──▶ [Web画面(キュー管理アプリ)]
                                          │ チケット番号/実行順序/AIモデルを登録
                                          ▼
                                     [キューDB]（全利用者共通）
                                          ▲
                                          │ 先頭チケットを取得
[Windowsタスクスケジューラ] ──一定間隔で起動──▶ [実行エンジン]
                                          │
                    ┌─────────────────────┼───────────────────────┐
                    ▼                     ▼                       ▼
              [Redmine API]        [GitHub Copilot CLI]      [Gitリポジトリ(固定・1つ)]
              チケット取得           実装AI／レビューAI          チケット毎に新規ブランチ作成
              結果コメント登録        （モデルはチケット毎に指定）    コミット＋プッシュまで自動
```

## 4. 機能要件

### 4.1 Web画面（キュー管理アプリ）
- Windows統合認証でログインユーザーを識別する（認証基盤はWindows標準のものを利用）。
- キューは全利用者共通の1つとし、誰が登録したかを記録する。
- Redmineチケット番号を指定してキューに追加できる。
- キュー内チケットの実行順序を並べ替えできる（先頭から順に1件ずつ直列実行）。
- チケットごとに「実装用AIモデル」「レビュー用AIモデル」を指定できる（システム全体のデフォルト値を設定でき、未指定時はデフォルトを使用する）。モデルはGitHub Copilot CLIが対応するものから選択する。
- 実行中／待機中チケットの状態一覧を表示する。
- 各チケットの実行ログ（実装・レビューのやり取り、差分概要等）を閲覧できる。
- キュー全体を一時停止／再開できる。
- 実行中のチケットを手動で強制中断できる。
- 未実行のチケットをキューから削除できる。

### 4.2 実行エンジン
- Windowsタスクスケジューラにより一定間隔（設定値。時間帯の制限なし）で起動される。
- 起動時、キューが一時停止中でなければ、先頭の未処理チケットを1件取り出す。
- 対象Redmineチケットの情報（タイトル・説明・ステータス）をRedmine REST APIから取得する。
- 固定の対象リポジトリ内に、チケット番号を含む新規ブランチを作成する。
- 指定された「実装用AIモデル」でGitHub Copilot CLIを起動し実装させる。
- 実装後、指定された「レビュー用AIモデル」でGitHub Copilot CLIを起動しレビューさせる。
- レビューNGの場合、指摘内容を実装用AIに渡して再実装させる（自動差し戻しループ）。
  - 再実装ループが上限回数（設定値、例:3回）に達した場合はループを打ち切る。
- レビューOKの場合、変更をコミットし、対象ブランチをリモートへプッシュする（PR作成・マージは人が行う）。
- 処理結果をRedmineの当該チケットにコメントとして記録する。
  - 上限到達時は「要確認（人対応）」の旨をコメントし、当該チケットをキューから除外する。
- 1件の処理が異常終了しても、次回のスケジュール起動には影響しない。
- 実行エンジンが多重起動しないよう排他制御を行う。

### 4.3 Redmine連携
- 既存のRedmineサーバーを利用する（URL・APIキーを設定情報として保持する）。
- チケット情報取得・コメント追加に対応する。
- 完了ステータスへの変更は本仕組みでは行わず、最終的に人が手動で行う。

### 4.4 Git連携
- 対象リポジトリは1つに固定する（設定情報として保持）。
- チケットごとに新規ブランチを作成する。
- コミット・プッシュまでを自動化する。PR作成・マージは人が行う。

## 5. 非機能要件
- Web画面はLAN内に公開し、Windows統合認証でアクセス制御・利用者識別を行う。
- Redmine APIキー等の認証情報は平文コミットせず、設定ファイル／環境変数等で安全に管理する。
- 実行エンジンの異常終了が後続の定期実行に影響しないこと。
- 実行エンジンの多重起動防止（排他制御）を行うこと。
- 実行ログを保持し、Web画面から後から確認できること。

## 6. 制約事項
- GitHub Copilot CLI・Redmine APIの利用制限（レートリミット等）に従う。
- 完全自動マージは行わない（PR作成後のレビュー・マージは人が実施）。
- タスクスケジューラの起動間隔・再実装ループの上限回数は設定可能な値とし、初期値は今後決定する。

## 7. スコープ外
- Redmineチケットの起票・要件整理自体の自動化。
- 複数リポジトリの同時対応（当面は1リポジトリ固定）。
- 利用者ごとの個別キュー、細かい権限の使い分け。
- Redmine以外の課題管理ツールとの連携。
- PRの自動マージ。
- Redmineコメント以外の通知（メール・チャット通知等）。
